# Mini NPU Simulator

Codyssey Pre-course 3주차 미션으로 개발한 Python 기반 MAC(Multiply-Accumulate) 연산 시뮬레이터입니다.

## 1. 프로젝트 소개

2차원 숫자 배열로 표현한 Cross(십자가)와 X 패턴을 MAC 연산으로 판별합니다. 3×3 사용자 입력과 JSON 데이터 일괄 분석을 지원하며, 배열 크기에 따른 실행 시간을 측정합니다.

Python 표준 라이브러리만 사용하고, MAC 연산은 중첩 반복문으로 직접 구현했습니다.

## 2. 실행 환경

- 운영체제: Windows 11
- 개발 도구: Visual Studio Code
- Python: 3.15.0
- 외부 라이브러리: 사용하지 않음

## 3. 실행 방법

프로젝트 폴더에서 다음 명령어를 실행합니다.

```powershell
python main.py
```

실행 후 메뉴에서 원하는 기능을 선택합니다.

- `1`: 사용자 입력(3×3)
- `2`: data.json 일괄 분석
- `3`: 보너스 1 — 2D/1D MAC 성능 비교
- `4`: 보너스 2 — Cross/X 패턴 자동 생성
- `0`: 종료

`data.json`은 `main.py`와 같은 폴더에 배치합니다.

## 4. 주요 구현 기능

### MAC 연산

패턴과 필터의 같은 위치에 있는 숫자를 곱하고 결과를 모두 더합니다.

MAC 점수 = Σ(입력값 × 필터값)

N×N 배열에서는 한 필터에 대해 N²번의 위치별 곱셈을 수행합니다.

### 라벨 정규화

- `+`, `cross`, `Cross` → `Cross`
- `x`, `X` → `X`

정규화된 라벨을 기준으로 판정과 예상 정답을 비교합니다.

### 동점 처리

두 MAC 점수의 차이의 절댓값이 `1e-9`보다 작으면 `UNDECIDED`로 처리합니다.

### JSON 검증

패턴 키에서 크기 N을 추출하고, 해당 크기의 필터를 선택합니다. 행·열 개수, 숫자 자료형, 유한한 값 여부를 검증합니다. 잘못된 케이스는 FAIL로 기록하고 나머지 분석을 계속합니다.

## 5. 테스트 결과

### 사용자 입력 모드

3×3 Cross 입력과 Cross/X 필터를 사용한 결과:

- 필터 A 점수: 5.0
- 필터 B 점수: 1.0
- 판정: A

잘못된 숫자 개수 및 문자 입력 시 재입력 기능을 검증했습니다.

### JSON 분석 모드

학습용으로 생성한 5×5, 13×13, 25×25 Cross/X 패턴 6개를 분석한 결과:

- 전체 테스트: 6
- PASS: 6
- FAIL: 0

별도 실패 격리 테스트에서는 총 3개 중 PASS 2개, FAIL 1개가 출력되었으며, 실패 이후의 케이스도 정상적으로 분석되었습니다.

## 6. 성능 분석

### 크기별 MAC 연산 시간

| 크기 | MAC 횟수 | 평균 시간(ms) |
|---|---:|---:|
| 3×3 | 9 | 0.001635 |
| 5×5 | 25 | 0.001628 |
| 13×13 | 169 | 0.008301 |
| 25×25 | 625 | 0.052688 |

위 수치는 실습 5-3에서 측정한 결과입니다. MAC 함수 호출 구간을 대상으로 100회 반복 측정했습니다. 실행 환경에 따라 값은 달라질 수 있습니다.

### 보너스 1: 2D/1D MAC 비교

| 크기 | 2D 평균(ms) | 1D 평균(ms) | Flatten 평균(ms) |
|---|---:|---:|---:|
| 3×3 | 0.000872 | 0.000414 | 0.000536 |
| 5×5 | 0.001733 | 0.000940 | 0.001141 |
| 13×13 | 0.016250 | 0.005646 | 0.010490 |
| 25×25 | 0.033852 | 0.023177 | 0.025986 |

동일한 입력과 1,000회 반복 조건에서 측정했습니다. 모든 크기에서 2D와 1D의 MAC 점수가 일치했습니다.

이번 측정에서는 변환이 완료된 1D 배열의 MAC 연산 시간이 더 짧았습니다. 그러나 Flatten 변환 비용을 포함하면 1D 방식이 항상 유리한 것은 아닙니다.

## 7. 결과 리포트

### 실패 원인 분석

1. 정상 예제 데이터 6개는 모두 PASS였으며, 해당 데이터에서 관찰된 FAIL은 0개였습니다.
2. 이는 입력 패턴이 해당 필터와 일치하도록 생성되었고, MAC 계산 및 판정이 정상적으로 수행되었기 때문입니다.
3. `+`와 `cross`처럼 표현이 다른 라벨은 정규화하지 않으면 정답인데도 FAIL이 발생할 수 있습니다.
4. 따라서 JSON의 예상 정답과 필터 키를 `Cross` 또는 `X`로 정규화했습니다.
5. 행 또는 열 개수가 잘못되면 같은 위치의 값을 올바르게 비교할 수 없으므로 스키마 오류로 처리합니다.
6. 실제 오류 격리 테스트에서는 5×5 패턴의 한 행에 숫자가 4개만 있어 FAIL이 발생했습니다.
7. 해당 오류는 MAC 계산 로직 문제가 아니라 입력 데이터의 구조 문제로 분류했습니다.
8. 잘못된 케이스를 예외 처리한 후 다음 케이스의 분석을 계속하여 실패 격리 기능을 검증했습니다.
9. `NaN`과 무한대 같은 비유한 숫자는 정상적인 점수 비교를 방해할 수 있으므로 입력 검증 단계에서 거부합니다.
10. 부동소수점 연산에서는 매우 작은 수치 차이가 발생할 수 있으므로 epsilon 기반 동점 정책을 적용했습니다.
11. 동점 정책에 따라 점수 차이가 `1e-9`보다 작으면 `UNDECIDED`로 처리합니다.
12. `UNDECIDED`는 Cross/X 중 어느 쪽이 우세한지 결정할 수 없다는 뜻이며, 기대 라벨이 Cross 또는 X이면 FAIL로 기록합니다.

### 시간 복잡도 분석

13. MAC 연산은 N×N 배열의 모든 위치를 한 번씩 방문하는 중첩 반복문으로 구현했습니다.
14. 바깥쪽 반복문이 N번, 안쪽 반복문이 각 행마다 N번 실행되므로 위치별 곱셈 횟수는 N²입니다.
15. 따라서 필터 하나에 대한 MAC 연산의 시간 복잡도는 O(N²)입니다.
16. 3×3은 9회, 5×5는 25회, 13×13은 169회, 25×25는 625회의 위치별 곱셈을 수행합니다.
17. 배열 크기가 증가할수록 필요한 연산량이 제곱 비율로 증가하는 것을 확인할 수 있습니다.
18. 실제 측정에서는 3×3과 5×5의 평균 시간이 비슷했지만 13×13과 25×25에서는 증가하는 경향이 나타났습니다.
19. 짧은 연산의 측정 시간은 타이머 비용, 운영체제 상태, Python 실행 환경 등의 영향을 받을 수 있습니다.
20. 따라서 실제 측정 시간이 N²에 정확히 비례하지 않더라도 중첩 반복문의 구조를 근거로 O(N²)를 설명할 수 있습니다.
21. 2D와 1D 방식 모두 모든 원소를 한 번씩 처리하므로 MAC 계산 자체의 시간 복잡도는 O(N²)입니다.
22. 1D 배열은 인덱싱 구조가 단순하여 이번 실험에서 연산 시간이 짧았지만, 변환 비용과 데이터 재사용 여부를 함께 고려해야 합니다.

## 8. 보너스 과제

### 보너스 1 — 1차원 배열 변환

2차원 배열을 길이 N²의 1차원 리스트로 변환하고 동일한 데이터로 MAC 점수와 실행 시간을 비교했습니다.

### 보너스 2 — Cross/X 패턴 자동 생성

사용자가 입력한 3 이상의 홀수 크기 N에 대해 N×N Cross와 X 패턴을 자동 생성합니다.

3, 5, 7, 13, 25 크기의 생성과 MAC 점수 검증에 성공했습니다. 짝수, 3 미만의 값, 숫자가 아닌 입력에 대한 오류 처리도 확인했습니다.
